# Инструкция по запуску

Пошаговый запуск MESSD тремя способами:

1. [Локально](#1-локальная-разработка) — приложения на Node.js, база и TURN в Docker. Удобнее всего для разработки.
2. [Полностью в Docker](#2-всё-в-docker) — ничего, кроме Docker, ставить не нужно.
3. [Продакшен](#3-продакшен) — на сервере с доменом и HTTPS.

В конце — [проверка](#проверка-что-всё-работает), [тесты](#тесты) и [частые проблемы](#частые-проблемы).

## Что понадобится

| Инструмент                                    | Версия                                      | Нужен для          |
| --------------------------------------------- | ------------------------------------------- | ------------------ |
| Docker Desktop или Docker Engine с Compose v2 | актуальная                                  | всех способов      |
| Node.js                                       | 24 LTS (`.nvmrc`)                           | способа 1 и тестов |
| pnpm                                          | 12 (через Corepack)                         | способа 1 и тестов |
| Браузер                                       | актуальные Chrome, Edge, Firefox или Safari | звонков            |

Проверка:

```sh
docker compose version
node -v
```

## 1. Локальная разработка

### Шаг 1. Node.js и pnpm

```sh
nvm install
nvm use
corepack enable
```

`nvm` возьмёт версию из `.nvmrc`. Corepack поставит pnpm той версии, что указана в `package.json`.

### Шаг 2. Зависимости

```sh
pnpm install
```

Во время установки mediasoup скачает готовый бинарник медиасервера под вашу систему.

### Шаг 3. Переменные окружения

```sh
cp .env.example .env
```

Значения по умолчанию подходят для работы на своём компьютере. Ничего менять не нужно.

### Шаг 4. PostgreSQL и TURN

```sh
docker compose up -d postgres turn
```

PostgreSQL поднимется на порту 5432, coturn — на 3478.

### Шаг 5. Приложения

```sh
pnpm dev
```

Turborepo запустит три сервиса:

| Сервис | Адрес                                                       |
| ------ | ----------------------------------------------------------- |
| web    | <http://localhost:5173>                                     |
| api    | <http://localhost:3000/api/health>                          |
| core   | <http://localhost:4000/health>, медиа на портах 40000–40001 |

Миграции базы применятся автоматически при старте `api`. Сервисы перезапускаются при изменении кода, интерфейс обновляется без перезагрузки.

### Шаг 6. Открыть приложение

Откройте <http://localhost:5173>, введите имя и нажмите «Новый звонок». Чтобы позвонить самому себе, откройте ссылку комнаты в другом браузере или в окне инкогнито.

Остановка: `Ctrl+C` в терминале с `pnpm dev`, затем `docker compose down`.

## 2. Всё в Docker

### Шаг 1. Переменные окружения

```sh
cp .env.example .env
```

### Шаг 2. Сборка и запуск

```sh
docker compose up --build
```

Первая сборка занимает несколько минут. Запустятся `postgres`, `turn`, `api`, `core` и `web` на тех же портах, что и в способе 1. Приложение откроется на <http://localhost:5173>.

### Шаг 3. Работа с кодом (по желанию)

В соседнем терминале:

```sh
docker compose watch
```

Изменения в `apps/*/src` и `packages` синхронизируются в контейнеры, сервисы перезапускаются сами. После изменения `package.json` образ пересоберётся.

Остановка: `docker compose down`. Чтобы удалить и данные базы — `docker compose down -v`.

> Способы 1 и 2 занимают одни и те же порты. Запускайте только один из них.

## 3. Продакшен

### Шаг 1. Сервер и домен

- Linux-сервер с публичным IPv4, установлены Docker Engine и Compose v2.
- A-запись домена (например, `messd.app`) указывает на IP сервера.
- В файрволе открыты порты:

| Порт        | Протокол  | Для чего                     |
| ----------- | --------- | ---------------------------- |
| 80, 443     | TCP       | сайт, API, WebSocket (Caddy) |
| 443         | UDP       | HTTP/3                       |
| 40000–40015 | UDP и TCP | медиа (mediasoup)            |
| 3478        | UDP и TCP | TURN                         |
| 5349        | TCP       | TURN поверх TLS              |
| 49160–49200 | UDP       | реле TURN                    |

### Шаг 2. Код

```sh
git clone <адрес репозитория> messd
cd messd
```

### Шаг 3. Файл `.env`

Создайте `.env` и подставьте свои значения:

```env
NODE_ENV=production
LOG_LEVEL=info
DOMAIN=messd.app

POSTGRES_USER=messd
POSTGRES_PASSWORD=<длинный случайный пароль>
POSTGRES_DB=messd

RTC_ANNOUNCED_ADDRESS=<публичный IP сервера>
MEDIASOUP_WORKERS=4
MAX_PEERS=50
ROOM_CLOSE_DELAY_MS=60000
PEER_RECONNECT_GRACE_MS=20000
RATE_LIMIT_MAX=30

TURN_SECRET=<длинный случайный секрет>
TURN_REALM=messd.app
TURN_URLS=turn:messd.app:3478?transport=udp,turn:messd.app:3478?transport=tcp,turns:messd.app:5349?transport=tcp
TURN_CERTS_DIR=/etc/letsencrypt/live/messd.app
```

Случайные пароль и секрет можно получить командой `openssl rand -base64 32`.

`MEDIASOUP_WORKERS` — обычно число ядер сервера, но не больше 16: по одному медиапорту из диапазона 40000–40015 на воркер.

### Шаг 4. Сертификат для TURN

Сертификат для сайта Caddy получит сам. Для TURN поверх TLS положите `fullchain.pem` и `privkey.pem` в папку `TURN_CERTS_DIR`. Например, через certbot:

```sh
certbot certonly --standalone -d messd.app
```

Выполните это до первого запуска, пока порт 80 свободен. Без сертификата TURN работает только по портам 3478 (UDP/TCP).

### Шаг 5. Запуск

```sh
docker compose -f compose.prod.yaml up -d --build
docker compose -f compose.prod.yaml ps
```

Все сервисы должны быть в статусе `healthy` или `running`. Сайт откроется по адресу `https://<ваш домен>`.

### Обновление

```sh
git pull
docker compose -f compose.prod.yaml up -d --build
```

Активные звонки на время перезапуска `core` переподключатся автоматически.

### Логи и резервная копия

```sh
docker compose -f compose.prod.yaml logs -f core
docker compose -f compose.prod.yaml exec postgres pg_dump -U messd messd > backup.sql
```

Подробнее о продакшене — в [deployment.md](deployment.md).

## Проверка, что всё работает

1. `http://localhost:5173/api/health` (в проде — `https://<домен>/api/health`) отвечает `{"status":"ok"}`.
2. На главной после ввода имени видно «Привет, <имя>».
3. «Новый звонок» → лобби с превью камеры. Если что-то сказать, индикатор микрофона покажет «Микрофон слышит вас».
4. Откройте ссылку комнаты во втором браузере и нажмите «Подключиться» в обоих. Каждый должен видеть и слышать другого.
5. У таймера звонка значок закрытого замка — сквозное шифрование включено.

## Тесты

Локально (нужен запущенный PostgreSQL из шага 4 способа 1):

```sh
pnpm --filter @messd/e2e exec playwright install
pnpm test
```

Playwright сам поднимет сервисы на отдельных портах (3100, 4100, 5180), поэтому тесты не мешают `pnpm dev`.

В контейнере, со всеми браузерами:

```sh
docker compose --profile test run --rm e2e
```

Проверки кода:

```sh
pnpm lint
pnpm typecheck
pnpm format:check
```

## Частые проблемы

| Симптом                                                                                | Причина и решение                                                                                                                                                                                         |
| -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Порт 5432, 3000, 4000 или 5173 занят                                                   | Остановите другой экземпляр (`docker compose down` или `Ctrl+C` в `pnpm dev`) либо освободите порт                                                                                                        |
| `ERR_PNPM_IGNORED_BUILDS` при установке                                                | Запустите `pnpm install` из корня репозитория: там в `pnpm-workspace.yaml` разрешены сборки mediasoup                                                                                                     |
| Камера не включается при открытии по IP из локальной сети                              | Браузеры дают доступ к камере только по HTTPS или на `localhost`. Открывайте <http://localhost:5173> либо используйте продакшен-сборку с HTTPS                                                            |
| Собеседник с другого устройства подключается, но видео нет и висит «Переподключаемся…» | Медиасервер объявляет адрес `RTC_ANNOUNCED_ADDRESS`. Для звонков из локальной сети укажите в `.env` IP компьютера в сети, а в проде — публичный IP сервера. Порты 40000+ (UDP и TCP) должны быть доступны |
| В проде не работает звонок из корпоративной сети                                       | Проверьте `TURN_URLS`, `TURN_SECRET` и открытые порты TURN (3478, 5349, 49160–49200)                                                                                                                      |
| Пишет «Комната не найдена» на только что созданную ссылку                              | Комната закрывается, если пустует 60 секунд после звонка (`ROOM_CLOSE_DELAY_MS`), или если в неё никто не вошёл за 24 часа (`ROOM_TTL_HOURS`). Создайте новый звонок                                      |
| `Could not find profile folder` при запуске Firefox в Playwright на macOS              | Известная несовместимость сборки Firefox из Playwright с новыми версиями macOS. Запускайте тесты в контейнере: `docker compose --profile test run --rm e2e`                                               |
